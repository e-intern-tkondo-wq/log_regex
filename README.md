# ログメッセージ正規表現変換システム

## 概要

このレポジトリでは、ログファイルのメッセージを数行ずつ正規表現に変換し、SQLiteデータベースに格納するシステムを提供します。各メッセージに対して正規表現への変換を行い、変換後の正規表現が元のメッセージに正しくマッチするか検証します。エラーが発生した場合は処理を停止し、エラーがなければ次の行数に進むという段階的な処理を行います。

### 主な機能

- ログメッセージの正規表現への自動変換
- 変換結果の自動検証（元のメッセージとのマッチング確認）
- SQLiteデータベースへの格納
- 段階的な処理（10行、50行、100行、1000行、全行）
- エラー発生時の自動停止
- パイプライン処理による複数行数の順次実行
- ユニークなデータベースの作成（重複除去）

## セットアップ

### 必要な環境

- Python 3.7以上
- SQLite3（Python標準ライブラリに含まれる）

### インストール

特別なインストールは不要です。Python標準ライブラリのみで動作します。

```bash
# 必要なパッケージは標準ライブラリのみ
# sqlite3, re, argparse, pathlib は標準で含まれています
```

## 使用方法

### 1. 基本的な使用方法

指定した行数だけログメッセージを処理します：

```bash
python create_regex_db.py -n 10    # 10行処理
python create_regex_db.py -n 50    # 50行処理
python create_regex_db.py -n 100   # 100行処理
python create_regex_db.py -n 1000  # 1000行処理
python create_regex_db.py          # 全行処理
```

行数を指定しない場合は、ファイル全体を処理します：

```bash
python create_regex_db.py          # 全行処理
```

### 2. パイプライン処理

複数の行数を順次実行するパイプラインスクリプトを使用します：

```bash
python run_pipeline.py
```

このスクリプトは以下の順序で実行します：
1. `-n 10` を実行
2. エラーがなければ `-n 50` を実行
3. エラーがなければ `-n 100` を実行
4. エラーがなければ `-n 1000` を実行
5. 最後に全行処理（オプション無し）を実行

いずれかのステップでエラーが発生した場合、処理は停止します。

### 3. データベースの内容を確認

格納されたデータを確認するには：

```bash
python view_regex_db.py
```

### 4. ユニークなデータベースの作成

既存の `regex.sqlite3` から重複を除去し、ユニークなメッセージのみを含む新しいデータベース `regex_unique.sqlite3` を作成します：

```bash
python create_unique_db.py
```

このスクリプトは：
- 既存の `regex.sqlite3` からユニークなメッセージを抽出
- 新しい `regex_unique.sqlite3` を作成
- 重複のないメッセージのみを格納
- 統計情報を表示（元のDBと新しいDBの比較）

## 各スクリプトの詳細

### create_regex_db.py

ログメッセージを正規表現に変換し、SQLiteデータベースに格納するメインスクリプトです。

#### 機能

1. **正規表現変換**: `abstract_message()` 関数を使用してメッセージを正規表現パターンに変換
   - 16進数（`0x[0-9A-Fa-f]+`）はそのまま保持
   - 空白文字は `\s+` に変換
   - 数字は `\d+` に変換
   - その他の文字はエスケープ

2. **データベース格納**: 変換した正規表現と元のメッセージをペアで格納（カラムはID message ruleの３列）


3. **検証**: 格納した正規表現が元のメッセージにマッチするか確認
   - マッチしない場合はエラーを出力し、処理を停止
   - 正規表現のコンパイルエラーも検出

#### コマンドライン引数

- `-n, --num-lines`: 処理する行数を指定（オプション）

#### 出力

- 処理済み行数の進捗表示（100行ごと）
- 処理完了時の統計情報
- エラー発生時の詳細情報

### view_regex_db.py

データベースに格納されたデータを表示するスクリプトです。

#### 表示内容

- テーブル構造
- 総レコード数
- サンプルデータ（最初の10件）
- ユニークな正規表現ルール数

### run_pipeline.py

複数の行数設定を順次実行するパイプラインスクリプトです。

#### 機能

- `-n 10`, `-n 50`, `-n 100`, `-n 1000`, 全行 の順で `create_regex_db.py` を実行
- 各ステップでエラーが発生した場合、処理を停止
- 全てのステップが成功した場合、成功メッセージを表示

#### カスタマイズ

`run_pipeline.py` の `num_lines_list` を編集することで、実行する行数を変更できます：

```python
num_lines_list = [10, 50, 100, 1000, None]  # None は全行処理を表す
```

### create_unique_db.py

既存の `regex.sqlite3` からユニークなメッセージのみを抽出して、新しいデータベース `regex_unique.sqlite3` を作成するスクリプトです。

#### 機能

- 既存の `regex.sqlite3` から `DISTINCT` を使用してユニークなメッセージを抽出
- 新しい `regex_unique.sqlite3` を作成（既存のファイルは上書き）
- 重複のないメッセージとその正規表現ルールを格納
- 元のデータベースと新しいデータベースの統計情報を比較表示

#### 実行結果

- 元のデータベースの総レコード数とユニークなメッセージ数を表示
- 新しいデータベースの総レコード数、ユニークなメッセージ数、ユニークな正規表現ルール数を表示
- 重複がないことを確認

## データベース構造

### テーブル: messages

| カラム名 | 型 | 説明 |
|---------|-----|------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | レコードID（自動採番） |
| message | TEXT NOT NULL | 元のログメッセージ |
| regex_rule | TEXT NOT NULL | 変換後の正規表現パターン |

### インデックス

- `idx_regex_rule`: `regex_rule` カラムにインデックスを作成（検索性能向上のため）

## 正規表現変換の仕組み

### abstract_message() 関数の処理フロー

1. **16進数の検出**: `0x[0-9A-Fa-f]+` パターンを検出
2. **プレースホルダー置換**:
   - 空白文字 → `___WS___`
   - 数字 → `___NUM___`
3. **エスケープ処理**: 特殊文字をエスケープ
4. **正規表現パターンへの復元**:
   - `___WS___` → `\s+`
   - `___NUM___` → `\d+`
5. **16進数パターンの追加**: `0x[0-9A-Fa-f]+` をそのまま追加

### 変換例

```
元のメッセージ: "Linux version 5.15.0-1076-nvidia"
正規表現: "Linux\s+version\s+\d+\.\d+\.\d+\-\d+\-nvidia"
```

## エラーハンドリング

### エラーが発生した場合

1. **マッチングエラー**: 正規表現が元のメッセージにマッチしない場合
   - エラーメッセージを表示
   - 処理を停止
   - エラーが発生した行の情報を出力

2. **正規表現コンパイルエラー**: 生成された正規表現が無効な場合
   - エラーメッセージを表示
   - 処理を停止
   - エラーの詳細を出力

3. **ファイル読み込みエラー**: 入力ファイルが見つからない場合
   - `FileNotFoundError` を発生
   - 処理を停止

## 注意事項

- データベースファイル（`regex.sqlite3`）は既存のものを使用します。新規作成する場合は、既存のファイルを削除してください
- 入力ファイルのパスは `create_regex_db.py` 内でハードコードされています。変更する場合はスクリプトを編集してください
- 大量のデータを処理する場合、処理時間がかかる可能性があります

## トラブルシューティング

### データベースがロックされている

複数のプロセスが同時にデータベースにアクセスしようとしている可能性があります。他のプロセスを終了してから再実行してください。

### メモリ不足

大量のデータを処理する場合、メモリ不足が発生する可能性があります。`-n` オプションを使用して、処理する行数を制限してください。

### 正規表現のマッチングエラー

変換された正規表現が元のメッセージにマッチしない場合、エラーメッセージが表示されます。該当するメッセージの内容を確認し、必要に応じて `abstract_message()` 関数のロジックを調整してください。
